Локальная копия запущена на отдельном origin `http://127.0.0.1:4182/`, чтобы отделить тестовые данные от рабочей панели на порту 4173.

- **12 браузерных сценариев: 10 PASS, 2 FAIL.** Оба падения относятся к одному новому дефекту BUG-002.
- Повторный запуск `node --test core.test.mjs qa-hour-01.test.mjs`: **26 PASS, 0 FAIL**, exit 0.

- Код приложения и зависимости не менялись. Это отчёт о проверке, а не исправление дефектов или подтверждение полной готовности проекта.

Браузерные действия выполнены через интерфейс: выбор файла, импорт, редактирование строк и перезагрузка. Полные массивы заявок сравнивались через доступный на странице read-only WebMCP `list_requests`; сообщения и отображение проверялись по DOM. JSON рядом — запись результатов этого прогона, **не автоматический браузерный тест**.

## BUG-002 — перезагрузка меняет принятые значения, повторный импорт создаёт дубликат

**Предлагаемый приоритет:** P2. **Статус:** воспроизведён, не исправлен.

Минимальное воспроизведение на отдельной чистой копии с 50 демонстрационными записями:

1. Сгенерировать файлы командой ниже и импортировать `formula-like.csv` через «Импорт заявок» → «Файл CSV» → «Импортировать».
2. Найти `QA-FORMULA`: ID равен `=QA-FORMULA`, тема равна `=1+1`; всего 51 запись.
3. Перезагрузить страницу. Фактически перед ID и темой появляется апостроф, хотя импорт был принят без предупреждения.
4. Снова импортировать тот же файл. Ожидается обновление существующей заявки, всего 51. Фактически добавляется новая запись, всего 52, рядом существуют `=QA-FORMULA` и `'=QA-FORMULA`.

В полном прогоне UI-11–UI-12 счётчик был 53 → 54 из-за записей предыдущих сценариев. Минимальные шаги выше выделены для повторения; отдельный минимальный прогон не выполнялся.

По исходнику причина связана с загрузкой сохранённого JSON через `importCSV(exportCSV(parsed))` в `app.js`. `exportCSV()` добавляет апостроф к формульным префиксам для безопасного открытия CSV в таблицах. При восстановлении данных это меняет исходные значения, включая ключ ID. Аналогичный путь есть в обработчике события storage; межвкладочное воспроизведение в этом этапе не выполнялось.

Рекомендация разработчику: отделить проверку сохранённых записей от CSV-экспорта и сохранять идентификаторы без изменений. Защиту формульных значений при экспорте оставлять. После исправления повторить UI-11–UI-12 и проверить целостность ID после перезагрузки.

## Повторить проверку

Из папки `service-desk`:

```sh
node qa-stage-02-fixtures.mjs
node --test core.test.mjs qa-hour-01.test.mjs
node --test qa-known-bugs.test.mjs
```

Первая команда создаёт 8 обезличенных CSV в `.qa-stage-02/`, включая файл больше лимита. Она не запускает браузерные сценарии. Последняя команда пока ожидаемо завершается с кодом 1 из-за BUG-001.

Для отдельного тестового origin под PowerShell:

```powershell
$env:PORT = '4182'
node server.mjs
```

Использовать новый профиль браузера или свободный порт с чистыми тестовыми данными; не очищать рабочие данные пользователя. Выполнить сценарии таблицы последовательно. Нажатие «Сбросить» сбрасывает фильтры, а не хранилище.

# AI Sana

MVP для хакатона HackAlem AI: бизнес превращает потребность в понятную задачу, студенты предлагают решение, бизнес выбирает команду.

## 1. Что делает проект

Основной сценарий: **идея → черновик → рейтинг → публикация → отклик → выбор команды**.

Геймификация направлена на бизнес: подробное описание получает больше баллов и располагается выше в каталоге. Команды выбирают задачи самостоятельно. Автоматического назначения нет.

## 2. Возможности

- Три шага заполнения карточки, сохранение черновика и восстановление по ссылке.
- Объяснимый рейтинг 0–100, четыре уровня, подсказки о следующем улучшении.
- Проверка заглушек, однообразных повторов и дублирования ключевых полей.
- Каталог с поиском, фильтрами по навыкам и статусу, сортировкой по рейтингу.
- Кабинеты «Мои задачи» и «Мои отклики».
- Предложение команды из 3–5 участников; один отклик пользователя на задачу.
- Просмотр предложений и контактной почты владельцем задачи.
- Подтверждение выбора команды; приём откликов и редактирование после выбора закрываются.
- Защита от перезаписи устаревшей версией карточки, контроль прав на сервере.
- Необязательный GPT-помощник: структурированный бриф, вопросы по пробелам, просмотр перед применением в пустые поля.
- Адаптивный интерфейс, доступные подписи полей, фокус ошибок, защита от ухода с несохранённой формой.

## 3. Технологии

React 19, TypeScript, Vinext/Vite, маршруты Next App Router, Cloudflare Workers и D1 (SQLite), Drizzle для схемы и миграций, Zod для валидации, Lucide для иконок. ИИ — OpenAI Responses API со строгой JSON-схемой.

Node.js 22.13+; проверено на Node.js 24.20. Требуется npm.

## 4. Архитектура

```text
Браузер (React)
  └─ /api/tasks, /api/responses, /api/assistant
      ├─ аутентификация и проверка владельца
      ├─ Zod + правила качества + контроль версии
      ├─ подготовленные SQL-запросы → D1
      └─ серверный запрос → OpenAI (если настроен ключ)
```

`app/components/` — каталог, редактор, карточка и отклики.
`lib/quality.ts` — единые правила рейтинга для клиента и сервера.
`lib/repository.ts` — SQL с параметрами и атомарными проверками состояния.
`lib/assistant.ts` — интеграция с GPT и проверка ответа.
`db/schema.ts`, `drizzle/` — схема и миграции.

## 5. Установка и запуск

```sh
npm ci
npm run build
```

Для **новой локальной базы** один раз выполните обе миграции по порядку:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_friendly_crusher_hogan.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_concerned_may_parker.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_kind_tarantula.sql
npm run dev
```

Откройте `http://localhost:5173`. База сохраняется в `.wrangler/state`. Не применяйте первую миграцию повторно к существующим таблицам. Если первая версия уже запускалась, достаточно второй миграции.

### Отдельные аккаунты бизнеса и студента

Страница `/login` поддерживает два тестовых аккаунта приложения: `business` и `student`. ChatGPT для них не нужен. Пароли выдаются владельцем и не публикуются в репозитории. Дополнительный вход через ChatGPT сохранён для ранее созданных задач.

Для своего развёртывания выполните `node scripts/create-demo-accounts.mjs ../private-accounts.json`. Скрипт создаёт случайные пароли и сохраняет конфигурацию `APP_ACCOUNTS` в локальном `.dev.vars`. Для публикации перенесите это значение в одноимённый секрет Sites и опубликуйте версию. Файл с паролями должен оставаться вне GitHub. Не заменяйте существующие идентификаторы аккаунтов: на них ссылаются задачи и отклики.

Пароли хранятся в виде PBKDF2-SHA256 хешей с отдельной солью (100 000 итераций; выдаваемые пароли случайные, 144 бита). Сессии живут 8 часов: HttpOnly, SameSite=Lax, Secure на HTTPS; в D1 хранится только хеш случайного токена. Выход отзывает сессию на сервере. Вход ограничен 30 попытками на сетевой адрес за 15 минут. Бизнес создаёт задачи и выбирает команду; студент откликается. Все права проверяются на сервере.

Это два подготовленных аккаунта для MVP, а не открытая регистрация. Нет восстановления пароля, проверки email и пользовательского управления аккаунтами. Адреса `@demo.invalid` вымышленные и не используются для связи. Для ChatGPT-пользователей сохранён исходный сценарий, где роль определяется авторством задачи.

## 6. Подключение GPT

Скопируйте `.dev.vars.example` в `.dev.vars` и заполните файл локально:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Перезапустите dev-сервер после изменения. На Sites ключ настраивается как серверная переменная окружения с тем же именем. Локальный файл не переносится в облако автоматически.

Ключ не попадает в браузер, Git и архив исходников. В OpenAI передаются исходное описание и текущие поля только после нажатия «Помочь с описанием». Запрос использует `store: false`, таймаут 45 секунд и лимит 10 попыток на пользователя в час. Это не отменяет правил хранения данных самого провайдера. ИИ не должен выдумывать отсутствующие факты; пользователь проверяет предложение перед применением. Без ключа работают ручной ввод, перенос описания в поле проблемы, рейтинг и весь основной сценарий.

Документация: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

## 7. Воспроизводимый пример

Полный демонстрационный бриф находится в `lib/example.ts`. В пустом каталоге есть «Посмотреть пример»; также доступен `/?view=detail&task=example`. Это явно обозначенная вымышленная задача, её нельзя принять за реальную заявку.

1. Войдите и создайте новую задачу. Вставьте: «Менеджеры записывают обращения в нескольких таблицах. Статусы теряются, руководитель не видит просроченные заявки. Нужен веб-прототип с фильтрами и назначением ответственных».
2. Перенесите описание в поле проблемы или запросите GPT. Заполните название, краткое описание и желаемый результат.
3. Добавьте контекст, материалы на выходе, сроки и критерии. Наблюдайте изменение рейтинга. Сохраните и перезагрузите страницу: черновик останется.
4. Опубликуйте и найдите задачу в каталоге.
5. На опубликованном сайте другой пользователь отправляет предложение команды из 3–5 участников.
6. Автор задачи подтверждает выбор. У студента в «Мои отклики» появляется результат, новые отклики закрыты.

Сценарий презентации: [DEMO.md](DEMO.md).

## 8. Проверки

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

Для локального API-сценария при работающем `npm run dev`:

```sh
node scripts/verify-local.mjs
```

Скрипт создаёт временную задачу, проверяет публикацию, права, повторные отклики, конфликт версий, выбор и блокировку изменений, затем удаляет только свои тестовые записи. Для смены бизнес/студент использует локальную SQL-фикстуру владельца: это не проверка входа двух настоящих аккаунтов. Не обращается к живому GPT. Модульные тесты проверяют в том числе структуру AI-запроса и ошибки модели на имитированных ответах.

## 9. Данные и внешние сервисы

Задачи и отклики хранятся в D1. Приватные черновики видит автор. Публичная карточка не содержит email владельца. Отклики и контакт студента доступны ему самому и владельцу задачи. Учебный пример поставляется с исходниками; внешние датасеты не используются. Авторизация — Sites, генерация по желанию — OpenAI. Уведомления по почте не отправляются: контакт открывается через `mailto:`.

## 10. Ограничения MVP

- Рейтинг — эвристика полноты, длины и разнообразия текста; он не оценивает достоверность, пользу или выполнимость задачи. Полностью защитить рейтинг от осмысленно выглядящего мусора эта эвристика не может.
- На запрос каталога загружается до 500 свежих записей; пагинации и рекомендаций по профилю пока нет.
- Один пользователь представляет одну команду в одном отклике; общего командного аккаунта нет.
- После выбора команды нет отмены выбора. Нет чата, файлов, уведомлений, модерации, удаления задач через интерфейс и админ-панели.
- Для проверки без ChatGPT доступны отдельные аккаунты бизнеса и студента; пароли выдаются владельцем. Открытой регистрации и восстановления пароля нет.
- Живой GPT требует действующего ключа и баланса API; без них AI-ветка не проверена на реальном провайдере.
- Платформенные ресурсы Sites необходимо настроить при переносе за пределы этого проекта.

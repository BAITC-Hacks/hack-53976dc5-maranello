## 2. Какую проблему решает проект

Бизнесу бывает трудно превратить короткое описание своей потребности в задачу, которую студенческая команда сможет оценить и выполнить. Без контекста, сроков и критериев готовности приходится тратить время на уточнения.

AI Sana помогает **представителю бизнеса** подготовить структурированный бриф и показывает, какие сведения ещё нужны. **Студенты** видят открытые задачи, выбирают интересные проекты и предлагают свой подход. Представитель бизнеса просматривает предложения и самостоятельно выбирает команду.

Главная геймификация адресована бизнесу: чем полнее описание, тем выше его рейтинг и положение задачи в каталоге. Система не назначает команды автоматически.

## 3. Что реализовано

### В приложении и веб-сервисе

- Вход в отдельные подготовленные аккаунты `business` и `student` по логину и паролю.
- Редактор карточки в три шага: суть задачи, ожидаемый результат, условия и публикация.
- Сохранение черновиков и опубликованных задач на сервере.
- Рейтинг полноты описания от 0 до 100, четыре уровня и конкретные подсказки для улучшения.
- Проверки текстовых заглушек, однообразных повторов и совпадения ключевых полей.
- GPT-помощник: структурирование исходного описания, предложение полей карточки и уточняющие вопросы.
- Просмотр предложения ИИ перед применением; заполненные пользователем поля сохраняются.
- Предпросмотр изменения рейтинга и блок «Что улучшилось» после применения ИИ.
- Каталог с поиском, фильтрами по навыкам и статусу, сортировкой по качеству описания.
- Разделы «Мои задачи» для бизнеса и «Мои отклики» для студента.
- Отклик с названием команды, составом из 3–5 участников и планом решения.
- Просмотр состава и предложений владельцем задачи; выбор команды с подтверждением.
- Закрытие приёма откликов и редактирования после выбора команды.
- Проверка прав на сервере, защита от повторного отклика и перезаписи устаревшей версии задачи.
- Обновление откликов при возвращении на страницу и периодическая проверка, пока карточка видима.

### В Android-оболочке

- Отдельная иконка и окно приложения с Android WebView.
- Кнопки «Назад», обновления и открытия текущей страницы во внешнем браузере.
- Индикатор загрузки, экран ошибки сети и повторная загрузка.
- Сохранение cookies сессии; восстановление состояния WebView.
- HTTPS, запрет смешанного HTTP/HTTPS-контента и доступа WebView к локальным файлам.
- Только разрешение `INTERNET`; API-ключ OpenAI и пароли не встроены в APK.

Android-приложение использует опубликованный веб-интерфейс. Бизнес-логика и база данных находятся на сервере, поэтому изменения веб-версии доступны через ту же оболочку.

## 4. Как работает решение

1. **Бизнес входит** в свой аккаунт и описывает проблему обычным текстом.
2. **Формирует карточку** вручную или запрашивает помощь ИИ. Помощник предлагает структуру и вопросы; бизнес проверяет сведения и применяет предложение.
3. **Уточняет описание:** цель, пользователей, данные, ожидаемые материалы, ограничения, сроки и критерии готовности. Рейтинг пересчитывается по правилам.
4. **Публикует задачу** в открытом каталоге.
5. **Студент выбирает задачу** и отправляет предложение от команды из 3–5 человек.
6. **Владелец задачи видит отклики** и подтверждает выбор команды.
7. **Обе стороны видят результат**, сохранённый в серверной базе после перезагрузки страницы.

Отклики видит именно владелец конкретной задачи. Вход через ChatGPT и вход `business` — разные учётные записи; роль бизнеса сама по себе не даёт доступа к чужим предложениям.

## 7. Установка и запуск

### Вариант A — установить готовый APK

1. Откройте [ссылку на APK](https://github.com/BAITC-Hacks/hack-53976dc5-maranello/raw/refs/heads/main/ai%20sana%20apk/AI-Sana.apk) на Android-телефоне либо передайте файл с компьютера.
2. Откройте файл и установите приложение. Если Android запросит разрешение выбранному источнику на установку APK, выполните этот шаг самостоятельно.
3. Запустите **AI Sana** при включённом интернете.
4. Используйте `business` или `student` и пароль, полученный у команды. Пароли не публикуются в README и репозитории.

Для установки через Android Debug Bridge на подключённое устройство с разрешённой USB-отладкой:

```sh
git clone https://github.com/BAITC-Hacks/hack-53976dc5-maranello.git
cd hack-53976dc5-maranello
adb install "ai sana apk/AI-Sana.apk"
adb shell am start -n kz.aisana.practice/.MainActivity
```

Для установки готового APK не нужны Node.js, Gradle или собственный OpenAI API-ключ.

### Вариант B — собрать Android-приложение из исходников

Понадобятся JDK 17+, Android SDK Platform 35 и Gradle, совместимый с Android Gradle Plugin 8.13.2. В репозитории есть конфигурация Gradle, но **нет Gradle Wrapper**; команда `./gradlew` не предусмотрена.

1. Клонируйте репозиторий командой выше.
2. Откройте папку `ai sana 2/android` в Android Studio, настройте Android SDK и совместимую среду сборки.
3. Укажите путь к SDK через `ANDROID_HOME` либо локальный `local.properties` с `sdk.dir`. Не коммитьте машинные пути.
4. При наличии настроенного Gradle в `PATH` выполните:

```sh
cd "ai sana 2/android"
gradle assembleDebug
```

Ожидаемый результат стандартной Gradle-сборки: `build/outputs/apk/debug/AI-Sana-Android-debug.apk`; точное имя можно посмотреть в этом каталоге. Установить собранный файл можно через `adb install <путь-к-файлу.apk>` или файловый менеджер телефона.

Публикуемый APK подписан отдельным демонстрационным ключом. Новая debug-сборка обычно имеет другую подпись и не обновит его поверх установленной версии. Для обновления требуется исходный ключ либо удаление предыдущей установки с потерей локальной сессии. Сам ключ в GitHub отсутствует.

Адрес сервиса задан константами `HOME` и `HOST` в `MainActivity.java`. Для подключения к своему HTTPS-развёртыванию измените обе константы и пересоберите APK.

### Вариант C — запустить веб-сервис локально

Этот вариант нужен для разработки сервера. Готовый APK продолжает обращаться к опубликованному сайту.

Требования: Node.js 22.13+ и npm. Из корня клонированного репозитория:

```sh
cd "ai sana 2"
npm ci
```

В этой копии исходников отсутствует `.openai/hosting.json`, который импортируется из `vite.config.ts`. Для **локального** запуска создайте минимальную конфигурацию D1 без идентификатора чужого размещения:

```sh
node -e "const fs=require('fs');fs.mkdirSync('.openai',{recursive:true});if(!fs.existsSync('.openai/hosting.json'))fs.writeFileSync('.openai/hosting.json',JSON.stringify({d1:'DB',r2:null},null,2));"
node -e "const fs=require('fs');if(!fs.existsSync('.dev.vars'))fs.copyFileSync('.dev.vars.example','.dev.vars');"
node scripts/create-demo-accounts.mjs ../../ai-sana-local-accounts.json
```

Последняя команда создаёт локальные аккаунты и записывает конфигурацию `APP_ACCOUNTS` в `.dev.vars`. Файл с паролями расположен **вне клонированного репозитория**. Запускайте создание аккаунтов один раз: существующие идентификаторы связаны с задачами и откликами.

Если нужен ИИ, заполните серверные переменные в `.dev.vars`, сохранив созданную строку `APP_ACCOUNTS`:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Без ключа доступны ручное заполнение, рейтинг, публикация и отклики. Затем соберите приложение и примените **три** миграции к новой локальной базе:

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_friendly_crusher_hogan.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_concerned_may_parker.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_kind_tarantula.sql
npm run dev
```

Откройте `http://localhost:5173/login`. Для существующей базы применяйте только ещё не применённые миграции. Локальные данные находятся в `.wrangler/state` и не связаны с облачной базой. После изменения `.dev.vars` перезапустите сервер. Для собственной облачной публикации необходимы отдельные ресурсы D1 и серверные переменные окружения.

## 8. Как жюри проверить решение

Попросите у команды пароли двух демонстрационных аккаунтов. Для быстрого знакомства можно начать с веб-версии без установки. Для полноценного сценария создайте **новую** задачу: после выбора команды повторный выбор для неё не предусмотрен.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Войти как `business`, открыть «Мои задачи» → «Новая задача» | Открывается редактор |
| 2 | Добавить название и проблему из примера ниже | Рейтинг отражает частично заполненную карточку |
| 3 | Нажать «Помочь с описанием», если ИИ подключён | Появляются предложение и уточняющие вопросы |
| 4 | Проверить факты, применить предложение или заполнить поля вручную | Рейтинг пересчитывается; после применения ИИ видны изменения |
| 5 | Сохранить черновик, обновить страницу и открыть его | Сохранённые поля восстановлены |
| 6 | Заполнить обязательные поля и опубликовать | Задача появляется в каталоге |
| 7 | Сменить аккаунт на `student`, найти ту же задачу | Доступна форма отклика |
| 8 | Ввести команду из трёх участников и предложение, отправить | Появляется статус рассмотрения |
| 9 | Войти как `business`, открыть эту задачу | Видны название, состав и план команды |
| 10 | Выбрать команду, подтвердить, обновить страницу | Сохраняется статус «Команда выбрана» |
| 11 | Снова войти студентом и открыть отклик | Отображается результат выбора |

**Исходное описание для примера:**

> Учебная сервисная компания ведёт заявки в нескольких таблицах. Менеджеры теряют сроки ответа, руководитель вручную собирает статусы. Нужна веб-панель для трёх менеджеров и руководителя: ответственный, статус и срок по каждой заявке. Дадим CSV с 50 вымышленными записями. За три недели нужны импорт, фильтр просроченных заявок и изменение статуса. Передать исходный код и инструкцию. Только тестовые данные, без CRM и отправки сообщений. Критерии: импортируются 50 строк, фильтр работает, изменения сохраняются после перезагрузки.

Пример названия — «[ДЕМО] Панель обращений». Команда — «Демо-команда»; участники — Алия, Данияр, Тимур, каждый с новой строки.

**Пример предложения:**

> Сначала согласуем поля CSV и макет, затем реализуем импорт заявок, фильтры и смену статусов. Проверим сохранение после перезагрузки. Передадим исходный код, тестовый файл и инструкцию по запуску.

На одном устройстве используйте «Сменить аккаунт». Для одновременного показа подойдут два устройства либо разные браузерные профили. Обычные вкладки одного браузера используют общую сессию.

### Проверки для разработчика

В папке `ai sana 2`:

```sh
npm test
npm run typecheck
npm run build
```

При запущенном локальном сервере и созданных локальных аккаунтах:

```sh
node scripts/verify-accounts.mjs http://localhost:5173 ../../ai-sana-local-accounts.json
```

Скрипт проверяет два входа, сохранение и публикацию задачи, отклик, выбор команды, ограничения прав и выход. Он создаёт тестовую задачу и оставляет её в базе. Модульные AI-тесты используют имитированные ответы; они не доказывают доступность внешнего API.

Для APK отдельно проверьте на телефоне установку, запуск, клавиатуру, кнопку назад, повторное открытие и восстановление после потери сети. В документации Android-проекта зафиксирована проверка сборки и подписи, но **нет подтверждения запуска на физическом устройстве или эмуляторе**.

## 9. Данные и интеграции

- **Ввод бизнеса:** описание задачи, организация, цель, пользователи, контекст, материалы, ограничения, срок, критерии готовности и навыки.
- **Ввод студента:** название команды, участники и предложение. Имя и email представителя связаны с учётной записью.
- **D1 / SQLite:** задачи, отклики, хеши сессионных токенов и счётчики ограничений. Приватный черновик доступен владельцу; отклик — автору отклика и владельцу задачи.
- **OpenAI:** по нажатию кнопки передаются исходное описание и текущий черновик. Ключ хранится на сервере. В запросе используются `store: false`, строгая JSON-схема и таймаут 45 секунд; результат дополнительно проверяется Zod. Настройка `store: false` сама по себе не является обещанием отсутствия хранения данных у провайдера.
- **Лимит ИИ:** до 10 попыток на пользователя в час; необходимы действующий серверный API-ключ и доступ к модели.
- **Авторизация:** подготовленные парольные аккаунты; для веб-версии также предусмотрен вход через ChatGPT.
- **Примеры:** `lib/example.ts` содержит учебную задачу. Внешние датасеты, RAG, собственное обучение модели и интеграция с CRM не реализованы. CSV в демонстрационном брифе — данные предполагаемого студенческого проекта, а не функция импорта в AI Sana.
- **Контакты:** для обычных email интерфейс использует `mailto:`. Адреса `@demo.invalid` у тестовых аккаунтов вымышленные; почтовые уведомления не отправляются.

## 10. Ограничения текущей версии

- APK — WebView-оболочка онлайн-сервиса; офлайн-работы и отдельной локальной базы задач нет.
- Android-приложение не опубликовано в Google Play. Проверка подписи APK не заменяет испытание на реальном устройстве.
- В APK вход через ChatGPT открывается во внешнем браузере; его сессия не переносится в WebView. Для сценария внутри приложения предназначены `business` и `student`.
- Нет самостоятельной регистрации, восстановления пароля, подтверждения email и управления аккаунтами пользователями.
- Рейтинг оценивает полноту, длину и разнообразие текста. Он не подтверждает достоверность, полезность, выполнимость задачи или качество будущего решения.
- ИИ может ошибаться или вернуть ответ, не прошедший проверку. Предложения необходимо проверять; при сбое остаётся ручное заполнение.
- Сравнение «до помощи ИИ → сейчас» относится к текущей сессии редактора; история изменений рейтинга не хранится как отдельная сущность.
- Один аккаунт студента может отправить один отклик на задачу. Участники записываются текстом; приглашений в команду и подтверждения состава нет.
- Нет чата, push/email-уведомлений, загрузки файлов, модерации, админ-панели и удаления задач через интерфейс.
- Выбор команды нельзя отменить в текущем интерфейсе; после выбора редактирование и новые отклики закрыты.
- Каталог получает до 500 свежих записей; нет пагинации и рекомендаций по профилю студента.
- В репозитории нет измерений эффекта на реальных компаниях: заявлений о числе клиентов, экономии времени или результатах пилота здесь не делается.

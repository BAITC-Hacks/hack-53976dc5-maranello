# Project handoff — backend v0.2.0 + frontend v0.1.0

Обновлено: 2026-09-23. Реализован React + Vite frontend для демонстрации
сквозного сценария. Backend, SQLite и API в frontend-сессии не изменялись.
Рабочее название интерфейса — «Практика»; язык — русский.

## Frontend: что готово

- Dashboard с двумя направлениями: бизнес и студенческая команда; переключатель
  демо-роли в шапке, без регистрации.
- Создание из короткого текста, результат анализа и три вопроса из API.
  Mock/fallback честно обозначен как базовый/резервный анализ.
- Редактор всех десяти полей и темы; справа серверный рейтинг 0–100,
  breakdown и рекомендации. После кнопки «Сохранить» рейтинг обновляется.
  При несохранённых правках показано предупреждение; расчёта баллов на клиенте нет.
- Подтверждение и публикация — отдельные действия. Нулевой рейтинг разрешён.
- Каталог с серверной сортировкой, точным фильтром по теме, фильтром готовности
  и пагинацией. Высокий рейтинг выделен, низкий остаётся видимым.
- Полная карточка, форма предложения, список предложений бизнеса, ручные
  принятие/отклонение с подтверждением. Автоматического назначения нет.
- Loading skeletons, ошибки с повтором, пустые состояния, восстановление текста
  форм через localStorage, адаптивная боковая навигация, keyboard focus и reduced motion.
- Все карточки, показатели и предложения поступают из API. В компонентах нет
  mock-массивов. Примеры внутри placeholder не являются данными каталога.

### Запуск frontend

Backend должен быть запущен на `http://127.0.0.1:8000` по инструкции ниже.
Во втором терминале из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5173**. Vite проксирует `/api` на backend:8000.
Настройка по умолчанию не требует frontend `.env`. Для другого API скопировать
`frontend/.env.example` в `frontend/.env` и установить `VITE_API_BASE_URL`
(с окончанием `/api`); при другом origin сервер должен разрешать CORS.
Секретный AI-ключ остаётся только в backend `.env`.

```bash
cd frontend
npm run build
npm run preview
```

Preview доступен на `http://127.0.0.1:4173` и также проксирует `/api` на :8000.
Для отдельного размещения `dist/` нужны SPA fallback на `index.html` и proxy `/api`
или корректный `VITE_API_BASE_URL` во время сборки. Проверена среда Node 26.9.0,
npm 11.19.1; Vite 7 требует Node 20.19+ или 22.12+.

### Ограничения frontend

- Переключение роли — демонстрация, не авторизация. Доступ к чужим задачам сервером
  не ограничен; не использовать для публичного продакшена.
- API не отдаёт «мои задачи», поэтому «Рабочие задачи» хранит только ID задач,
  созданных в этом браузере. Очистка localStorage удаляет эти ссылки, но не задачи БД.
- Поле industry в API отсутствует: на карточках используется реальный `topic`.
  Тема фильтруется точным совпадением без учёта регистра.
- Счётчики предложений собираются из существующего API предложений (до четырёх
  параллельных запросов), без нового backend endpoint. Подходит для масштаба MVP.
- Опубликованная карточка недоступна для правок согласно текущему контракту.
  Решение по предложению окончательное; максимум одна принятая команда.
- Внешний AI не включался и не проверялся живым ключом в frontend-сессии.
  Демонстрация полностью работает с существующим mock/fallback backend.
- README и презентация в этой сессии не изменялись.

## Что реализовано

1. Draft из короткого описания с AI/mock-анализом.
2. Недостающие поля и минимум три вопроса (API выдаёт ровно три).
3. Structured card из описания/ответов, частичное редактирование.
4. Ручное подтверждение и публикация, без порога рейтинга.
5. Рейтинг 0–100 сразу после создания, ответов и редактирования; breakdown,
   missing_fields, recommendations; GET /api/tasks/{id}/rating.
6. Каталог: рейтинг по возрастанию/убыванию, newest, фильтры topic и level.
7. Предложения: team_name, solution_idea, plan, estimated_duration, prototype_url,
   необязательный contact. При создании всегда pending.
8. Только ручные accepted/rejected; одно принятое предложение на задачу.
9. OpenAI Responses adapter, Pydantic-валидация, проверка источников и offline fallback.
10. Неразрушающая SQLite-миграция v1 → v2, дополненные seed-данные и тесты.

## Важные изменения контракта

- Рейтинг больше не null до подтверждения и не исчезает после редактирования.
  После правки подтверждение сбрасывается, а рейтинг пересчитывается сразу.
- Добавлен Task.rating с score, level, breakdown (массив компонентов), missing_fields,
  recommendations. Старые readiness_score/readiness_level/score_breakdown сохранены.
- Сортировка каталога по умолчанию rating_desc; topic — явная тема пользователя,
  нормализованная trim/casefold, а не AI-классификация.
- POST предложения теперь требует solution_idea, plan, estimated_duration вместо
  старого message. Старый формат POST возвращает 422. В ответе message сохранён.
- Низкий балл, включая 0, не блокирует публикацию и отклик.
- Явно пустые ответы считаются ответами для шага подтверждения, но баллов не дают.

Бизнес-правила и допущения: [SPEC.md](SPEC.md).

## AI и запрет на выдумывание фактов

TaskAI.prepare выполняет извлечение полей и выбор приоритетов уточнения.
Внешней модели разрешены только ссылки field/source_id на целые исходные фрагменты.
Свободного текста для заполнения карточки в схеме ответа AI нет.
Сервер берёт значения из пользовательского ввода; недопустимые ссылки/дубли/
структуры отклоняет. Явные метки, ответы и ручные правки нельзя переопределять.
Вопросы выводятся из нейтральных шаблонов, чтобы не внедрять выдуманные предпосылки.

AI_PROVIDER=mock по умолчанию: без сети/ключа, извлечение явно размеченных полей,
свободный текст сохраняется в context. AI_PROVIDER=openai включает Responses API
только при создании и сохранении ответов. Модель — OPENAI_MODEL, default gpt-4o-mini.

Если ключа нет либо AI отвечает с ошибкой, неверным JSON, отказом, неполным ответом
или неподтверждёнными ссылками, запрос выполняется с fallback. Провайдер и причина
видны в ai_analysis. Ключ/текст запроса не логируются. Автоповторов запросов нет,
таймаут HTTP-операций 12 секунд. Рейтинг всегда считает backend, не AI.

Важно: внешний API в этой сессии реально не вызывался — ключ не использовался.
HTTP-адаптер, корректный разбор и отказоустойчивость проверены через MockTransport.
Живой демонстрационный сценарий проверен с mock. Семантическая классификация
фрагмента моделью может ошибаться, поэтому ручная проверка карточки обязательна.

## SQLite и демонстрационные данные

При запуске, seed или python -m database.migrate выполняется идемпотентное обновление:
новые колонки добавляются, таблицы не удаляются. Старый message копируется в
solution_idea. Неизвестные plan, estimated_duration, prototype_url, topic остаются
пустыми. Производные рейтинги пересчитываются, пользовательский updated_at сохраняется.

Перед обновлением сделана database/app.pre-v2.db — резервная копия исходной v1.
Рабочая база — database/app.db. Обе исключены из git.
Сравнение с резервной копией подтвердило сохранность пользовательских данных всех
5 исходных задач и 4 предложений; изменялись только производные поля рейтинга.

В seed теперь 8 задач и 5 предложений. На существующей БД добавились три задачи:

| ID | Задача | Тема | Состояние / рейтинг |
| --- | --- | --- | --- |
| 6 | Отчёт о посещаемости | аналитика | published / 70 ready |
| 7 | Реестр оборудования | автоматизация | published / 100 priority |
| 8 | Тема пока не определена | образование | draft / 0 draft |

Повторный seed: 0 задач / 0 предложений. Существующие записи не перезаписываются;
у исходных задач после миграции topic остаётся пустым. В новой БД все seed-задачи
получат темы из seed_data.json.

Пример из API_CONTRACT.md дополнительно создал через настоящий HTTP задачу ID 9
(«Отчёт о посещаемости», published / 70 ready) и предложения ID 6 accepted, ID 7 rejected.
Итого после backend-проверки было 9 задач, 7 предложений; 6 задач опубликованы.
Браузерные frontend-тесты добавляют свои демонстрационные записи.
ID приведены для текущей БД, клиенты должны брать ID из ответов API.

## Как запустить

Из корня проекта (окружение .venv уже подготовлено):

```bash
source .venv/bin/activate
python -m database.seed
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

Для чистой установки сначала python3 -m venv .venv, затем активация и
python -m pip install -r backend/requirements.txt. Миграция вызывается автоматически;
вручную — python -m database.migrate. Относительный DATABASE_URL считается от корня.
Если порт 8000 занят оставленным сервером, используйте его либо остановите перед новым запуском.

```bash
python -m pytest backend/tests -q
curl http://127.0.0.1:8000/health
```

Для внешнего AI настройте локальный .env по .env.example, задайте AI_PROVIDER=openai,
OPENAI_API_KEY и при необходимости OPENAI_MODEL, затем перезапустите сервер.
Появление ключа само по себе не включает внешнюю отправку данных.

## Сохраняющиеся ограничения

- Нет авторизации/проверки владельцев: только доверенная локальная демонстрация.
- Опубликованная карточка не редактируется; нет отмены публикации и пересмотра решения.
- Семантика заполненности проверяется только списком заглушек; произвольный текст
  может получать баллы. Рейтинг не является оценкой достоверности или качества.
- Нет версионирования конкурентных правок карточки, дедупликации команд и загрузки файлов.
- У новой схемы есть только переход v1 → v2, не общий фреймворк миграций.
- Frontend реализован отдельным этапом без изменения backend; см. начало документа.

# Демонстрация «Практика» — до 5 минут

Целевое время **4:30**, запас **30 секунд**. Один браузер, роли переключаются
кнопками **Бизнес / Команда**. Student = «Команда». Регистрации и паролей нет.

## Подготовка до запуска таймера

1. Выполнить установку и запуск по [README](../README.md). Для предсказуемых
   вопросов оставить `AI_PROVIDER=mock`. Если меняли его — перезапустить backend.
2. Проверить `/health`, открыть http://127.0.0.1:5173/tasks/new, выбрать «Бизнес».
3. Держать этот документ рядом для копирования текстов. Масштаб браузера 100%.
4. Для чистого показа использовать отдельную БД и новое приватное окно браузера:
   localStorage хранит ссылки и несохранённые формы, привязанные к ID задач.
5. После пробной репетиции оставить её опубликованную карточку и предложения
   в запасных вкладках. Записать фактический ID из URL; ID не фиксированы.
6. Не запускать тесты во время демонстрации: они добавляют свои записи.

## Сценарий и реплики

### 0:00–0:25 — Business: короткий draft

Реплика: «Бизнесу сложно сразу написать техническое задание. Начнём с одной фразы».
На `/tasks/new` вставить:

- **Опишите задачу или проблему:** `Заявки мастерской теряются в чатах`
- **Тема задачи:** `демо-мастерская`

Нажать **Разобрать задачу**.

### 0:25–1:10 — AI questions → ответы

Показать три вопроса и исходное описание.
Реплика: «Анализ сохраняет известные факты и спрашивает о недостающем. Сейчас
используем локальный базовый режим; внешний AI подключается отдельно».

| Вопрос | Ответ для вставки |
| --- | --- |
| Какую проблему нужно решить? | Собрать заявки в одном реестре |
| Какой конкретный результат должна предоставить команда? | Реестр с поиском и статусами |
| Как вы проверите, что задача решена успешно? | Все тестовые заявки находятся по номеру |

Нажать **Собрать карточку**.

### 1:10–1:50 — Generated card → rating → improvement

Показать заполненные поля и рейтинг **50 / 100, Часть описана**.
Реплика: «Рейтинг измеряет полноту постановки. За контекст и проблему — 20,
за результат — 15, за критерии — 15. Материалов пока нет».

В редакторе заполнить:

- **Название:** `Реестр заявок мастерской — демо`
- **Данные и материалы:** `Обезличенный CSV с заявками`

Нажать **Сохранить**. Показать **70 / 100, Много деталей**.
Реплика: «Добавили материалы — получили ещё 20 баллов. Остальные пробелы видны
в рекомендациях. Рейтинг не запрещает публикацию даже при нуле».

### 1:50–2:15 — Publication

Нажать **Подтвердить карточку**, затем **Опубликовать задачу**.
Реплика: «Карточку проверяет человек. Подтверждение и публикация — отдельные действия».
После публикации откроется `/tasks/<id>`. Запомнить эту карточку.

### 2:15–2:45 — Student: catalog → task

Переключить роль **Команда**, открыть **Каталог задач**.
В фильтре темы ввести `демо-мастерская`, нажать **Применить тему**;
выбрать уровень **Много деталей** и сортировку **Сначала новые** (`newest`).
Открыть только что созданную задачу (при повторной репетиции она будет первой).
Реплика: «Студенты видят опубликованные задачи, сравнивают готовность и выбирают
задачу под свои возможности». Нажать **Предложить решение**.

### 2:45–3:35 — Student: proposal

| Поле | Текст |
| --- | --- |
| Название команды | Demo Team |
| Идея решения | Сделаем локальный реестр заявок с поиском |
| План работы | Разобрать CSV, создать форму, проверить поиск |
| Оценка времени | 5 часов |
| Контакт (необязательно) | demo-team@example.com |
| Ссылка на прототип | Оставить пустой |

Нажать **Отправить предложение**, затем **Вернуться к задаче**.
Реплика: «Команда предлагает идею, план и срок. Отправка не назначает её исполнителем».

### 3:35–4:15 — Business: proposal → accept

Переключить **Бизнес**, нажать **Смотреть предложения**.
Показать идею и план Demo Team. Нажать **Принять команду**, затем **Да, принять**.
Показать выбранную команду. Перезагрузить страницу — решение сохраняется.
Реплика: «Бизнес принимает решение вручную. На задачу можно выбрать одну команду».

### 4:15–4:30 — Завершение

Реплика: «Мы прошли путь от одной фразы до согласованного предложения команды.
Карточка помогает уточнить задачу, рейтинг показывает пробелы, а окончательные
решения остаются у бизнеса».

Оставшиеся 30 секунд — запас на навигацию и реакцию интерфейса.

## Ожидаемые контрольные точки

| Шаг | Результат |
| --- | --- |
| Короткое описание | draft, 10 баллов за контекст |
| Три ответа | draft, 50 / workable |
| Материалы + Сохранить | draft, 70 / ready |
| Подтвердить | confirmed, ещё не в каталоге |
| Опубликовать | published, видна в каталоге |
| Отправить предложение | pending, команда ещё не выбрана |
| Принять и подтвердить | accepted, сохраняется после reload |

Не заполняйте остальные поля для этой репетиции: тогда баллы будут ровно 50 → 70.
Рейтинг обновляется после **Сохранить**, а не во время набора текста.

## Если что-то пошло не так

- Нет связи: проверить оба терминала и `/health`, нажать «Повторить» после
  восстановления сервера. Ввод форм сохраняется локально.
- Пустой каталог: сбросить фильтры и убедиться, что была именно публикация.
- Другие вопросы: проверить `AI_PROVIDER=mock` и точный текст нового draft.
- Уже выбрана команда: создать новую задачу для полного сценария. Отмены решения нет.
- Если за 20–30 секунд восстановиться не удалось, открыть вкладки подготовленной
  репетиции и показать сохранённую карточку, рейтинг и принятое предложение.
  Честно обозначить, что это результат предварительного прогона.
